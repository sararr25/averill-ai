## Problem Statement

Users can lose orientation or see internal exceptions instead of a recoverable next action.

## Solution

Make navigation, answers and recovery usable with keyboard, zoom and assistive technology.

## User Stories

1. As an employee, I want to navigate without a mouse, so that I can complete my work confidently without a test guide.
2. As an employee, I want to know where focus moved, so that I can complete my work confidently without a test guide.
3. As an employee, I want to return focus after closing a reader, so that I can complete my work confidently without a test guide.
4. As an employee, I want to hear answer status announced, so that I can complete my work confidently without a test guide.
5. As an employee, I want to understand validation errors, so that I can complete my work confidently without a test guide.
6. As an employee, I want to recover after a provider timeout, so that I can complete my work confidently without a test guide.
7. As an employee, I want to read at 200 percent zoom, so that I can complete my work confidently without a test guide.
8. As an employee, I want to use a narrow window, so that I can complete my work confidently without a test guide.
9. As an employee, I want to use a wide window efficiently, so that I can complete my work confidently without a test guide.
10. As an employee, I want to reduce motion without losing feedback, so that I can complete my work confidently without a test guide.
11. As an employee, I want to distinguish states without color, so that I can complete my work confidently without a test guide.
12. As an employee, I want to stop an operation from every relevant view, so that I can complete my work confidently without a test guide.

## Implementation Decisions

- Extend existing semantic labels, focus recovery and reduced-motion patterns.
- Keep raw diagnostics out of the main answer while retaining inspectable technical detail.
- Verify real contrast and screen-reader behavior rather than inferring them from static markup.

## Testing Decisions

- Existing four-role accessibility matrix plus keyboard/focus workflows and separate native VoiceOver acceptance.
- Test observable behavior and employee-visible results, not private implementation structure. Prefer the existing authenticated renderer/IPC question → outbound preview → answer seam, following the Pro renderer and contextual bridge prior art. Preserve isolated synthetic accounts; company/public evidence, Stop/logout and content-bound consent are mandatory. The owner confirmed these testing seams on 30 October 2026.

## Out of Scope

Autonomous send, export or publication; arbitrary desktop observation or control; new screenshot/OCR permissions; automatic source approvals; cross-person memory; real employee data in Tavily; replacing human usability or real-platform acceptance with synthetic tests.
